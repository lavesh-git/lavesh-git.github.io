# 1.1 API Design

[API | API Request | REST API | https | http | Status Code | Client Server](<https://www.youtube.com/watch?v=b-ALmx5qA7I>)

API Design

Uniform Resource Identifies (URI) - URL identifies the resource on the server

Query Parameters - Used to filter specific results, sorting or showing specific data fields

Path Parameters - serve as placeholders for variable data that will be input into the URL, allowing to customize data response

Content Negotiation -

Refers to the process where the client and the server communicates about the data reporesentation which is acceptable for both of them. Indicate preferred response format eg: JSON, XML or HTML

TCP/IP -

  - Transmission Control Protocol / Internet Protocol

  - Suite of communication protocols used to connect hosts on the internet

  - Ordered, error-checked delivery of streams of bytes from one host to another

DNS -

  - Domain Name System

  - Interprets human-friendly hostnames into IP addresses which API needs for communicating

HTTP -

  - Protocol used for transmitting hydermedia data on the web eg: HTML pages or JSON from web API

  - Dictates how endpoints are defined, how data should be transferred (packaged and transported), and what status codes should be used to convey specific scenarios.

  - HTTP Methods -

    - Type of request a client can make to server

    - GET, POST, PUT, DELETE, PATCH

  - HTTP Status Code -

    - 3 digit numbers where the first digit defines the class of response

    - Last 2 digits doesn't have any categorization value

    - 200 = Successful HTTP request

    - 404 = Requested Resource not found or authorization error

  - HTTP Headers -

    - They are part of HTTP Request and Response message with type : {Standard, Non-standard, Common or Uncommon} headers

    - They define parameters like content type, authentication, response status, cookies etc

  - Cookies -

    - Small bits of data stored on user's browser that enables stateful HTTP sessions, by storing pertinent information between server communications

    - Cookies are useful when authentication is required. It can store session tokens thereby allowing users to stay logged in across multiple sessions or different web pages.

  - CORS -

    - Cross-Origin Resource Sharing is a mechanism that uses HTTP headers to tell browsers to give a web app running at one origin, access to selected resources from different origin

    - By default, browsers prohibits web pages from making requests to a different domain than the one the webpage came from

    - CORS is the guideline that lets you configure a set of rules on the server to define which types of cross-domain requests are allowed, providing much-needed flexibility without compromising security.

  - HTTP Caching -

    - HTTP caching is a key aspect of API design which involves storing copies of responses to HTTP requests to speed up future requests.

    - When an API receives the same request multiple times, instead of processing each request separately, it can use a previously stored response, thereby improving performance and efficiency.

    - The cache is governed by headers on the HTTP requests and responses.
