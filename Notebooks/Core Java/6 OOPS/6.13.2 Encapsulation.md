# 6.13.2 Encapsulation

Encapsulation

  - Bundling the data (fields) and methods that operate on the data into a single unit, typically a class.

  - Also helps in Data Hiding: It also aims to restrict direct access to some of an object's components, promoting controlled access through well-defined interfaces.

  - How to achieve Encapsulation
Encapsulation in Java is achieved by:

    1. **Declaring the fields (variables) of a class as private:** This ensures that the data cannot be accessed directly from outside the class.

    1. **Providing public getter and setter methods:** These methods allow controlled access to the private fields. The getter method retrieves the value, while the setter method sets or updates the value.

public class Employee {

private String name;  // Private field

private int age;

// Getter for name

public String getName() {

return name;

}

// Setter for name

public void setName(String name) {

this.name = name;

}

// Getter for age

public int getAge() {

return age;

}

// Setter for age

public void setAge(int age) {

if (age > 0) {  // Validating input

this.age = age;

} else {

System.out.println("Age must be positive!");

}

}

}

  - Data hiding
Data hiding is an essential aspect of encapsulation. By declaring the fields of a class as private, the internal state of the object is hidden from direct access by external code. This protects the object from unwanted modifications and ensures that the object maintains a valid state.

    - **Why Data Hiding is Important:**

      - Prevents unintended changes to the object's state.

      - Protects sensitive data.

      - Allows validation logic to be added in setter methods.

      - Loosely coupled code: Reduces coupling and improves maintainability.
**Example:** Without encapsulation:

public class WithoutEncapsulation {

public String name; // Public field

public static void main(String\[\] args) {

WithoutEncapsulation obj = new WithoutEncapsulation();

obj.name = "John";  // Direct access

System.out.println(obj.name);

}

}

      - With encapsulation:

public class WithEncapsulation {

private String name; // Private field

public String getName() {

return name; // Controlled access

}

public void setName(String name) {

this.name = name;

}

}

  - Tightly encapsulated class
A class is said to be **tightly encapsulated** if all its data members (fields) are declared private and access is controlled entirely through getter and setter methods. This ensures maximum control over the data.

    - **Characteristics of a Tightly Encapsulated Class:**

      - All variables are private.

      - No direct access to fields from outside the class.

      - All modifications and retrievals go through methods.
**Example of a Tightly Encapsulated Class:**

public class BankAccount {

private String accountNumber;

private double balance;

public String getAccountNumber() {

return accountNumber;

}

public void setAccountNumber(String accountNumber) {

this.accountNumber = accountNumber;

}

public double getBalance() {

return balance;

}

public void setBalance(double balance) {

if (balance >= 0) {  // Ensures valid data

this.balance = balance;

} else {

System.out.println("Balance cannot be negative!");

}

}

}

  - Getter and setter method in Java
Getter and setter methods are used to encapsulate data and provide controlled access to the fields.

    - **Getter Methods:**

      - Used to retrieve the value of a private field.

      - Public method.

      - Typically named getFieldName.

    - **Setter Methods:**

      - Used to modify the value of a private field.

      - Public method.

      - Typically named setFieldName.
**Advantages of Getters and Setters:**

    1. **Validation:** Logic can be added to setter methods to validate input.

    1. **Read-Only or Write-Only Fields:** By providing only getter or setter methods, you can create read-only or write-only fields.

    1. **Encapsulation:** Allows controlled access to private fields.
**Example with Validation:**

public class Product {

private double price;

// Getter method

public double getPrice() {

return price;

}

// Setter method

public void setPrice(double price) {

if (price > 0) {

this.price = price;

} else {

System.out.println("Price must be positive!");

}

}

}

  - Naming convention of getter and setter method
Java follows specific naming conventions for getter and setter methods to improve code readability and consistency. The conventions are as follows:
**For Non-Boolean Fields:**

    - Getter: get<FieldName>

    - Setter: set<FieldName>

      - The first letter of the field name is capitalized.

      - Example:

private String name;

public String getName() {  // Getter

return name;

}

public void setName(String name) {  // Setter

this.name = name;

}
