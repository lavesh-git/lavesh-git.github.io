# 9.7 Queue

[Java Collection Framework - Part 4: Queue Interface | Complete explanation in Hindi](<https://www.youtube.com/watch?v=jQmhRoks3V0>)

- Queue
In Java, you can create a queue using the Queue interface, which is part of the Java Collections Framework. The Queue interface is implemented by several classes, the most common being LinkedList and PriorityQueue.
**Example Using ****LinkedList
**Here’s how you can create and use a queue using the LinkedList class:

import java.util.Queue;

import java.util.LinkedList;

public class QueueExample {

public static void main(String\[\] args) {

// Create a Queue using LinkedList

Queue<String> queue = new LinkedList<>();

// Add elements to the Queue

queue.add("Element 1");

queue.add("Element 2");

queue.add("Element 3");

queue.add("Element 4");

// Display the Queue

System.out.println("Queue: " + queue);

// Access the head of the Queue without removing it

System.out.println("Head of the Queue: " + queue.peek());

// Remove elements from the Queue

System.out.println("Removed: " + queue.poll());

System.out.println("Removed: " + queue.poll());

// Display the Queue after removals

System.out.println("Queue after removals: " + queue);

// Check if the Queue is empty

System.out.println("Is the Queue empty? " + queue.isEmpty());

}

}

**Explanation**

  1. **Creating the Queue**:

    - We create a Queue instance using the LinkedList class. LinkedList is a common implementation of the Queue interface in Java.

  1. **Adding Elements**:

    - queue.add("Element"): Adds the specified element to the queue. If the queue is full (in bounded queues), this method throws an IllegalStateException. For LinkedList, there is no fixed capacity, so this won't happen.

    - Alternatively, you can use offer("Element"), which returns false if the queue is full, instead of throwing an exception.

  1. **Accessing the Head**:

    - queue.peek(): Retrieves, but does not remove, the head of the queue. It returns null if the queue is empty.

  1. **Removing Elements**:

    - queue.poll(): Retrieves and removes the head of the queue. It returns null if the queue is empty.

    - Alternatively, you can use remove(), which throws a NoSuchElementException if the queue is empty.

  1. **Checking if the Queue is Empty**:

    - queue.isEmpty(): Returns true if the queue contains no elements.

Output

Queue: \[Element 1, Element 2, Element 3, Element 4\]

Head of the Queue: Element 1

Removed: Element 1

Removed: Element 2

Queue after removals: \[Element 3, Element 4\]

Is the Queue empty? false

**Key Points**

  - **Queue Behavior**: A queue operates on a First-In-First-Out (FIFO) principle. The first element added is the first one to be removed.

  - **Common Operations**:

    - **Add**: add() or offer() to enqueue an element.

    - **Remove**: poll() or remove() to dequeue an element.

    - **Examine**: peek() to view the front of the queue without removing it.

**Example Using ****PriorityQueue**

If you want to create a queue where elements are ordered according to their natural ordering or a custom comparator, you can use PriorityQueue.

import java.util.PriorityQueue;

import java.util.Queue;

public class PriorityQueueExample {

public static void main(String\[\] args) {

// Create a Queue using PriorityQueue

Queue<Integer> priorityQueue = new PriorityQueue<>();

// Add elements to the PriorityQueue

priorityQueue.add(4);

priorityQueue.add(2);

priorityQueue.add(1);

priorityQueue.add(3);

// Display the PriorityQueue

System.out.println("PriorityQueue: " + priorityQueue);

// Remove elements from the PriorityQueue

while (!priorityQueue.isEmpty()) {

System.out.println("Polled: " + priorityQueue.poll());

}

}

}

PriorityQueue: \[1, 3, 2, 4\]

Polled: 1

Polled: 2

Polled: 3

Polled: 4

- **PriorityQueue Behavior**: Unlike LinkedList, which follows the FIFO principle, PriorityQueue orders elements based on their natural order or a custom comparator, which is why elements are dequeued in sorted order.

This should give you a good starting point to work with queues in Java!

- Deque
In Java, a Deque (Double-Ended Queue) is an interface that extends the Queue interface. It allows elements to be added or removed from both ends. Java provides several implementations of the Deque interface, such as ArrayDeque and LinkedList.
Here's how you can create and use a Deque in Java:
**Example Using ****ArrayDeque**

import java.util.Deque;

import java.util.ArrayDeque;

public class DequeExample {

public static void main(String\[\] args) {

// Create a Deque using ArrayDeque

Deque<String> deque = new ArrayDeque<>();

// Add elements to the Deque

deque.addFirst("Element 1 (First)");

deque.addLast("Element 2 (Last)");

deque.addFirst("Element 3 (First)");

deque.addLast("Element 4 (Last)");

// Print the Deque

System.out.println("Deque: " + deque);

// Access elements from the Deque

System.out.println("First Element: " + deque.getFirst());

System.out.println("Last Element: " + deque.getLast());

// Remove elements from the Deque

System.out.println("Removed First Element: " + deque.removeFirst());

System.out.println("Removed Last Element: " + deque.removeLast());

// Print the Deque after removals

System.out.println("Deque after removals: " + deque);

}

}

**Explanation:**

  1. **Creating the Deque**:

    - We create a Deque using ArrayDeque. You can also use LinkedList to implement a Deque.

  1. **Adding Elements**:

    - addFirst(E e): Adds an element at the front of the deque.

    - addLast(E e): Adds an element at the end of the deque.

  1. **Accessing Elements**:

    - getFirst(): Retrieves, but does not remove, the first element of the deque.

    - getLast(): Retrieves, but does not remove, the last element of the deque.

  1. **Removing Elements**:

    - removeFirst(): Removes and returns the first element of the deque.

    - removeLast(): Removes and returns the last element of the deque.

  1. **Printing the Deque**:

    - The Deque is printed before and after removing elements to show the changes.

Deque: \[Element 3 (First), Element 1 (First), Element 2 (Last), Element 4 (Last)\]

First Element: Element 3 (First)

Last Element: Element 4 (Last)

Removed First Element: Element 3 (First)

Removed Last Element: Element 4 (Last)

Deque after removals: \[Element 1 (First), Element 2 (Last)\]

This example demonstrates the basic usage of a Deque. You can perform other operations such as offerFirst(), offerLast(), pollFirst(), pollLast(), etc., depending on your specific needs.

**ArrayDeque Vs LinkedList**

ArrayDeque and LinkedList are two common implementations of the Deque interface in Java. Both have their strengths and weaknesses, and understanding the differences can help you choose the right one for your use case.

**1. ****Underlying Data Structure**

  - **ArrayDeque**:

    - Internally backed by a resizable array.

    - As the name suggests, it uses an array to store the elements in a contiguous block of memory.

  - **LinkedList**:

    - Internally backed by a doubly linked list.

    - Each element is stored in a node, with each node holding a reference to the previous and the next node.

**2. ****Performance**

  - **ArrayDeque**:

    - **Access and Modification**: Faster average performance for accessing elements due to better cache locality (since elements are stored in a contiguous array).

    - **Insertion and Deletion**: O(1) for adding or removing elements from either end (most of the time), but resizing the array when full can cause O(n) operations.

    - **Memory Usage**: Uses less memory per element because it does not require storing pointers to other nodes.

  - **LinkedList**:

    - **Access and Modification**: Slower access time (O(n)) because it has to traverse the list to reach an element.

    - **Insertion and Deletion**: O(1) for adding or removing elements from either end of the list.

    - **Memory Usage**: Uses more memory per element due to storing additional pointers (previous and next node references) for each element.

**Memory Overhead**

  - **ArrayDeque**:

    - Lower memory overhead compared to LinkedList because it doesn’t need to store extra pointers.

    - However, it may waste some memory due to unused array slots (when the array is not fully utilized).

  - **LinkedList**:

    - Higher memory overhead due to the storage of pointers to the next and previous elements in each node.

    - More flexible with memory usage, as it doesn’t need to allocate a large contiguous block like ArrayDeque.

**4. ****Usage Scenarios**

  - **ArrayDeque**:

    - Ideal for scenarios where you need fast access to elements and the size of the deque doesn't change dramatically.

    - Good for implementing stacks, queues, and other data structures where you need to frequently add and remove elements from both ends.

  - **LinkedList**:

    - Suitable for scenarios where you need to frequently insert or delete elements in the middle of the list.

    - Useful when the size of the deque is highly dynamic and you want to avoid the overhead of resizing the underlying array.

**5. ****Thread Safety**

  - Neither ArrayDeque nor LinkedList is thread-safe. If you need a thread-safe Deque, you should consider using ConcurrentLinkedDeque or wrapping them with Collections.synchronizedDeque().

**Summary**

  - **Choose ****ArrayDeque** if you need better performance for random access, generally faster operations due to contiguous memory allocation, and lower memory overhead.

  - **Choose ****LinkedList** if you need to frequently insert or remove elements at both ends, or at arbitrary positions within the deque, and are willing to accept slower access times and higher memory overhead.
