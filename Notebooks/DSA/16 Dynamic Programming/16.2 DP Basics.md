# 16.2 DP Basics

The quote associated with DP:

*"THOSE WHO DO NOT REMEMBER THE PAST ARE CONDEMNED TO REPEAT IT."*

The suggested way to go about solving DP problems is: Recursive solution -> memoization -> top-down

10 questions/patterns and their variations.

Tabulation : Bottom Up DP

Memoization : Top Down DP

Bottom up does not necessarily mean 0 to n it may be vice versa.

Top Down does not necessarily mean n to 0 it may be vice versa. Depends upon implementation.

Memoization -> Tabulation -> Space Optimization

T.C. , S.C                  T.C, S.C --------> S.C.\* (final soln)

Pre-requisite - Recursion, Backtracking

**Fibonacci Number**

0 indexing -

0  1  1  2  3  5  8  13  21 …

f(n) = f(n-1) +  f(n-2)

4th fibNum = f(4)

Recursion solution  -

```text
f(n){

If(n<=1) return n;

Return f(n-1) + f(n-2);

}
```

Red part is time waste because it recomputes f(2) which has been previously computed, and it is going to be same i.e. OVERLAPPING SUBPROBLEMS.

When same problem is solved again and again in difference recursion calls, we call It overlapping subproblems.

Memoization - We tend to store the value of sub-problem in some map/table, to avoid re-computation.

Fib(n) - one parameter --> 1D Array

Similarly f(3) need not be recomputed, just return the value from the map.

Subproblems are f(0), f(1) …. f(5) so maintain an array of size 6 and store -1 in it.

Everytime a problem was solved, I store it in an array, and whenever a problem is called, I check if its stored or not in the array i.e. solved priorly or not:
