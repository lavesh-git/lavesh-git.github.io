# 3.1.5 Layer 7: API  - REST, GRAPHQL, GRPC

All notes can be found in the API Section

[API](<onenote:API.one#section-id={A9176F5E-4786-094F-A9FC-D81EDC5D3187}&end&base-path=https://d.docs.live.net/1B496228341EAA92/NOTES/System%20Design%20-%20HLD>)

- **REST (Representational State Transfer):** REST is an architectural style, not a protocol. However, it is almost exclusively built on top of **HTTP/HTTPS**, which is a Layer 7 protocol. When you make a REST API call, your application is formatting data (usually JSON) and sending it via HTTP methods (GET, POST, PUT, DELETE) at Layer 7.

- **GraphQL:** Similar to REST, GraphQL is a query language and runtime for APIs. It is transport-agnostic in theory, but in practice, it is almost universally delivered over **HTTP/HTTPS** at Layer 7. It packs its queries into HTTP POST requests to fetch exactly the data specified.

- **gRPC (Google Remote Procedure Call):** gRPC is an RPC framework. It explicitly requires **HTTP/2** as its transport protocol, placing its foundation firmly at Layer 7.

    - *Note on Layer 6 (Presentation):* gRPC uses Protocol Buffers (Protobufs) to serialize and format data before sending it. Because Protobuf handles data formatting, serialization, and deserialization, this specific aspect performs the classic duties of **Layer 6 (The Presentation Layer)**, before handing the data off to HTTP/2 at Layer 7.
