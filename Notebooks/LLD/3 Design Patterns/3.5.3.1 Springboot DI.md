# 3.5.3.1 Springboot DI

**Framework Dependency Injection (DI) with Spring**

Till now, we have seen how to manually implement Dependency Injection via the three methods discussed earlier. However, there is another more efficient way to implement DI, which is through frameworks like **Spring**.

With **Framework DI**, the DI process is handled automatically by the framework itself. In Spring, dependencies are injected using annotations like **@Autowired** or **@Inject**. This eliminates the need for manually wiring objects, making the code cleaner, more scalable, and easier to maintain. The framework takes care of creating and managing dependencies, reducing boilerplate code and improving application structure.

In Spring Boot, Dependency Injection (DI) is the magic under the hood that allows the Spring IoC (Inversion of Control) container to manage objects and their relationships for you. Instead of manually creating objects using new, the container "injects" them where they are needed.

There are three primary ways to perform Dependency Injection in Spring Boot.
1. **Constructor Injection (The Gold Standard)
This** is the most recommended method. Dependencies are provided through the class constructor.
 \* How it works: You declare dependencies as final and provide a constructor.
 \* Why use it: It ensures the object is immutable and prevents "NullPointerExceptions" because the object cannot be created without its required dependencies.

@Service
public class UserService {
    private final UserRepository userRepository;

    // Standard constructor
    public UserService(UserRepository userRepository) {
        this.userRepository = userRepository;
    }
}

> Pro Tip: Since Spring 4.3, if a class has only one constructor, you don't even need the @Autowired annotation on it!
>

**2. Setter Injection**
Dependencies are provided through public setter methods after the object is instantiated.
 \* How it works: You use the @Autowired annotation on top of a setter method.
 \* Why use it: Use this for optional dependencies or if you need to re-inject or change a dependency later. It’s less "strict" than constructor injection.

@Service
public class EmailService {
    private NotificationConfig config;

    @Autowired
    public void setConfig(NotificationConfig config) {
        this.config = config;
    }
}

3. **Field Injection (The "Easy" Way**)
Dependencies are injected directly into the fields using reflection.
 \* How it works: You simply put @Autowired directly on the private variable.
 \* Why (not) to use it: While it looks the cleanest and requires the least code, it is generally discouraged. It makes unit testing harder (you can't easily mock the dependency without a framework) and hides required dependencies from the outside world.

@Service
public class ReportService {
    @Autowired
    private ReportGenerator reportGenerator; // Not recommended for production code
}
